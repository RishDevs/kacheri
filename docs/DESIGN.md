# Kacheri: visual design (binding; supersedes the earlier docket spec)

The source of truth is the approved mockups: `docs/design/Main.dc.html` (case view) and `docs/design/Bench.dc.html` (benchmark), from the Claude Design canvas https://claude.ai/artifact/8P2jGggwzTWJ4ZZKDZvZoD. Reproduce them exactly: same copy style, sizes, spacing, colours and fonts. Ignore the `<x-dc>`/`{{ }}`/script wrapper; it is the canvas runtime.

Principles: minimal, plain language, readable in 10 seconds. Answer three questions in order: what was proven, the proof, the fix. Everything else is secondary (collapsed `<details>`, small grey metadata).

- Fonts: Schibsted Grotesk (UI, 400/500/600/700), Martian Mono (code, numbers, SHAs only). Google Fonts.
- Colours: page #FFFFFF, text #111111, secondary #4A4A46, muted #6B6B66, rules #ECECE9, borders #D9D9D6, code bg #F7F7F5. PASS #1F4FD1 on #EAF0FD. FAIL / proven bug #C8361A on #FDECE7. No other colours. Light only (no dark mode, no theme toggle).
- Layout: max-width 1200px, 32px side padding, 48px top. Header: wordmark, nav (Reviews, Benchmark), "Runs on NVIDIA Nemotron · Nebius Token Factory".
- Case view: repo label → PR title (36/600) → verdict headline (56/700: "N bug(s) proven." or "No bugs proven.") + one plain sentence + buttons (Copy repro, Apply fix = copy patch) → 4-step row (Accuse / Prove / Decide / Fix with counts) → two columns: left = each proven bug (plain-language title, explanation, file:line, "The proof" grid Before/After/With fix × Run 1-3 with PASS/FAIL cells, then collapsed "Proof test" and "Why it was confirmed" (defense + judge)), then "Not shown as bugs · N" grey list with one plain reason each; right = "The change" (diff hunk around each proven line), "The fix" (remedy patch) + one line, then metadata list (Models, Cost, Time, Commits).
- Plain reasons for dismissed charges: passes on head → "Test passes on the new code"; also fails on base → "Same result before the change"; broken/errors → "Test could not run"; flaky → "Test result was not consistent"; rejected lint → "Test checked the wrong thing"; judge dismissed → "Judge: <short reason>"; sandbox → "Test tried something not allowed".
- Benchmark: label → question headline → one-sentence explainer → 3 big numbers (Bugs found, False alarms per PR, Cost per PR) → table (Reviewer, Bugs found, False alarms/PR, Precision, Cost/PR, Median time) → three short explainers of the item kinds. Show "—" until real results exist; a small grey "Sample data" note when data is a sample.
- Live progress: while a case runs, the verdict area shows the current step in plain words ("Writing proof tests…", "Running tests 12 of 24…", "Judge is deciding…", "Testing the fix…"). No spinners; text and the 4-step row update.
- Banned: gradients, glow, blur, shadows, emoji, icons-as-decoration, dark theme, cards everywhere, courtroom clip-art, the word "AI-powered", stamps/animations.
